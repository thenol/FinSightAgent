# MVP 范围与验收标准

## 1. MVP 目标

验证一条可持续运行的上市公司公告研究链路：系统能从官方公告形成有证据、可追踪、可审核的结构化研究卡片，并能对运行质量和成本进行基础评估。

## 2. 范围内

- 中国 A 股上市公司公告。
- 业绩预告、重大合同、并购重组、股东减持、监管处罚五类事件。
- RSS/官方公告入口、标准化、去重和事件聚类。
- 公司和证券实体对齐。
- 事实核验、公司影响分析、反方审查和结论合成。
- 原文证据引用、事件时间线、研究卡片和每日 Top 10。
- 人工审核、运行审计、失败恢复和基础离线评估。

## 3. 范围外

- 自动交易、调仓和个性化投资建议。
- 完整行业供应链传导和宏观政策分析。
- 分析师一致预期、期权和资金流驱动的完整预期差模型。
- 自动组合影响分析。
- 面向全市场新闻和社交媒体的实时覆盖。
- Kafka、ClickHouse、独立图数据库和 Temporal 的生产化建设。

## 4. 用户故事

MVP 覆盖[产品需求](./00-product-requirements.md)中的“发现并研究事件”和“审核争议报告”旅程；“跟踪结论变化”仅保留数据与版本基础，不在首期实现自动触发。

- 研究员可以查看当天高重要度事件、原公告证据及结构化分析。
- 审核员可以检查冲突和运行轨迹，并批准、退回、降级或终止。
- 用户可以查看公司事件时间线和每日重点事件简报。
- 管理员可以查看工作流成功率、成本、延迟和模型版本。

## 5. 功能验收

| ID | 能力 | 验收标准 |
| --- | --- | --- |
| AC-001 | 采集 | 保存原文、来源、发布时间、采集时间和内容 Hash；重复采集不生成重复文档 |
| AC-002 | 事件识别 | 五类事件均能输出符合 Schema 的类型、公司和发生时间 |
| AC-003 | 事件聚类 | 相同公告的转载不创建多个主事件，且保留全部来源 |
| AC-004 | 实体对齐 | 输出稳定证券 ID；歧义实体进入人工审核 |
| AC-005 | 事实核验 | 最终关键事实均关联可定位 Evidence ID |
| AC-006 | 公司分析 | 区分一次性与持续影响，至少给出基准情景和关键假设 |
| AC-007 | 反方审查 | 每份完整报告包含反方证据或明确说明未发现有效反证 |
| AC-008 | 报告 | 包含结论、置信度、时间范围、正反观点、观察项和重新分析条件 |
| AC-009 | 审核 | 可记录审核人、决定、原因、修改和时间 |
| AC-010 | 恢复 | Worker 中断后从已完成检查点恢复，不重复发布报告 |
| AC-011 | 审计 | 可从报告追溯到事件、文档、证据、Agent、工具和模型版本 |

## 6. 质量门槛

首批门槛应通过人工标注集校准后固化，建议初始目标：

- 五类事件分类准确率不低于 90%。
- 公司证券实体对齐准确率不低于 98%。
- 最终报告关键事实引用完整率为 100%。
- 引用内容与结论一致率不低于 95%。
- 无来源事实进入最终报告的比例为 0。
- 传闻被标记为已验证事实的比例为 0。
- 工作流成功或明确降级结束的比例不低于 98%。
- 同一事件的重复报告发布率低于 1%。

以上指标需同时记录样本量、事件类型分布和置信区间，不能只报告单一百分比。

## 7. 非功能验收

| ID | 验收标准 |
| --- | --- |
| NFR-001 | 高重要度公告从入库到研究卡片生成的 P95 时间在约定 SLA 内 |
| NFR-002 | 单事件配置硬预算，超限后能够停止并保存检查点 |
| NFR-003 | 所有写接口支持幂等，关键状态迁移具有审计记录 |
| NFR-004 | 服务重启不丢失已入库文档、事件或工作流状态 |
| NFR-005 | 未授权用户无法执行审核、发布或管理操作 |
| NFR-006 | 日志不包含密钥、完整授权新闻正文或敏感个人信息 |
| NFR-007 | 管理员可查询延迟、成本、成功率、人工审核率和引用完整率 |

具体延迟和成本 SLA 在完成真实数据压测后确定，不在缺乏基线时给出虚假精确值。

## 8. 实施里程碑

### M1：数据和事件底座

完成来源配置、公告采集、标准化、去重、实体表和事件表；用历史样本验证数据质量。

### M2：研究闭环

完成事实核验、公司分析、反方审查、结构化输出和检查点恢复。

### M3：产品输出

完成事件列表、详情、证据查看、研究卡片、审核台和每日简报。

### M4：评估与试运行

完成标注集、离线评估、运行指标和影子运行；根据结果校准阈值与预算。

## 9. 上线条件

- 所有 P0 功能验收通过。
- 关键质量门槛在冻结评估集上达标。
- 完成数据源许可、安全与合规检查。
- 失败恢复、数据库备份和回滚演练通过。
- 至少完成一段约定周期的影子运行，并确认不存在系统性事实错误。
- 明确值班负责人、人工审核流程和异常处置手册。

## 10. 后续阶段入口条件

只有当 MVP 的引用完整率、事实准确率、工作流稳定性和单事件成本达到目标后，才进入行业传导、市场预期、自动唤醒和组合影响分析。新增 Agent 必须说明它解决的独立问题、需要的数据及可量化收益。
