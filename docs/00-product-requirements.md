# 产品需求与用户旅程

## 1. 产品定位

FinSightAgent 面向需要快速处理上市公司公告的投研团队，将分散信息转化为有原始证据、正反观点和后续验证条件的事件研究卡片。产品辅助研究判断，不提供个性化投资建议，不自动交易。

## 2. 目标用户

| 角色 | 核心目标 | 主要操作 |
| --- | --- | --- |
| 研究员 | 快速发现重要事件并验证影响 | 浏览事件、查看证据、比较结论版本 |
| 审核员 | 控制事实与合规风险 | 处理冲突、批准或退回报告 |
| 研究负责人 | 掌握覆盖质量和团队关注重点 | 查看简报、质量指标与人工修改率 |
| 系统管理员 | 保证数据和工作流稳定 | 管理来源、阈值、权限和运行状态 |

只读用户和审核员必须分权；管理员不能因平台权限自动获得报告发布权。

## 3. 核心用户旅程

### 3.1 发现并研究事件

1. 系统采集公告并识别公司、事件类型和重要度。
2. 研究员在事件列表按日期、公司、类型、状态和重要度筛选。
3. 研究员打开事件详情，先查看官方原文和已验证事实，再查看分析结论。
4. 研究员检查反方观点、关键假设和重新分析条件。
5. 研究员收藏或订阅相关公司，等待后续变化。

### 3.2 审核争议报告

1. 系统因关键事实冲突或低置信度创建审核任务。
2. 审核员查看冲突两侧的原文定位、Agent 输出差异和影响范围。
3. 审核员选择批准、退回补充、降级为事实卡片或终止发布。
4. 系统记录决定、理由、修改和审核人，并从检查点继续执行。

### 3.3 跟踪结论变化

1. 新公告或预设指标触发已有事件。
2. 系统展示新增、修改和撤回事实，不隐藏旧版本。
3. 研究员比较结论、置信度与观察项的变化。

## 4. 产品信息架构

| 页面 | 主要内容 | 允许操作 |
| --- | --- | --- |
| 今日事件 | 事件排序、筛选、状态和关注标记 | 查看、筛选、订阅 |
| 事件详情 | 时间线、事实、证据、分析、反方观点 | 查看证据、比较版本 |
| 审核中心 | 待审原因、冲突和运行轨迹 | 批准、退回、降级、终止 |
| 公司时间线 | 公司历史事件和报告版本 | 按类型与时间筛选 |
| 每日简报 | Top 事件及摘要 | 查看、分享受控链接 |
| 运行与质量 | 延迟、成本、失败率和评估指标 | 管理员诊断与导出 |

## 6. 展示与交互原则

- 先证据后结论：关键事实和原文入口必须位于分析结论之前或可同时看到。
- 明确不确定性：区分已验证、冲突、未验证、假设和推论。
- 不用颜色单独表达方向，利好或利空必须同时提供文字标签。
- 所有报告显示生成时间、数据截止时间、版本和置信度依据。
- 被替代或撤回的结论仍可查看，但必须显著标记状态。

## 7. 产品成功指标

- 从公告公开到高重要度事件可见的时间。
- 研究员打开原始证据的比例和报告有效阅读率。
- 审核任务比例、平均处理时间和人工修改率。
- 关键事实引用完整率、引用一致率和实体对齐准确率。
- 相同覆盖量下，单事件研究时间和模型成本的变化。

市场收益指标用于验证信息价值，但不能替代事实准确性和研究流程质量。

## 8. 产品待决策事项

- 首期用户是内部投研团队还是同时面向外部客户。
- Top 10 排序是否允许用户自定义权重。
- 审核员能否直接修改 Agent 输出，还是只能退回并附加意见。
- 报告分享、导出和数据留存的授权边界。
