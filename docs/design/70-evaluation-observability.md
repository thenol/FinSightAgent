# DD-70 评估与可观测详细设计

## 1. 目标与边界

本模块衡量数据、事实、分析、市场结果和系统运行质量，并提供跨采集、事件、证据、工作流和报告的可追踪性。评估结果只追加，不改写历史报告或当时结论。

覆盖：FR-010、NFR-001～NFR-007，以及 MVP 质量门槛。

## 2. 评估层次

| 层次 | 主要指标 | 数据来源 |
| --- | --- | --- |
| 数据 | 采集召回、重复率、解析成功率 | Document、采集批次、标注集 |
| 事件 | 分类、聚类、实体准确率 | Event、MatchDecision、标注集 |
| 事实 | Claim 准确率、引用完整率、一致率 | Claim、Evidence、人工标签 |
| 分析 | 方向、反证召回、置信度校准 | Analysis、审核反馈、标签 |
| 市场 | 1/3/5/20 日异常收益 | ReportVersion、行情、基准 |
| 系统 | 延迟、成本、失败、恢复、审核率 | Trace、Workflow、ToolCall |

不同层次分别报告，避免用市场涨跌掩盖事实错误。

## 3. 时间截面与防泄漏

每个 EvaluationRun 固定：`dataset_version`、`as_of`、模型/Prompt/工具版本和行情数据版本。工作流只能读取 `published_at <= as_of` 且 `ingested_at <= as_of` 的数据。

市场验证的观察窗口从事件可交易后的首个有效交易时点开始；停牌、涨跌停和非交易日由市场日历工具确定。基准优先使用行业指数，同时报告宽基指数结果。

## 4. 离线评估集

样本按五类事件、来源、公司规模、时间和难度分层。数据集分为开发集、回归集和冻结验收集；冻结集标签对 Agent 执行不可见。

每个样本至少包含：允许使用的文档快照、正确事件类型与实体、关键 Claim、证据定位、冲突标签、期望降级/审核路径。标签修改形成新版本，不覆盖旧版本。

## 5. 指标定义

- 分类准确率：正确事件类型数 / 已标注样本数。
- 实体对齐准确率：正确稳定证券 ID 数 / 有明确实体样本数。
- 引用完整率：有有效 Evidence 的关键事实数 / 关键事实总数。
- 引用一致率：Evidence 实际支持的引用数 / 全部引用数。
- 置信度校准：按置信度分桶计算 ECE，并报告 Brier Score。
- 工作流成功率：成功或明确降级结束数 / 启动工作流数。
- 恢复成功率：从检查点恢复后安全终止数 / 恢复尝试数。

所有比例同时报告分子、分母、事件类型分布和置信区间。

## 6. 市场验证

对报告方向计算事件后 1、3、5、20 个交易日收益、行业调整收益和宽基调整收益。报告：均值、中位数、胜率、样本量和置信区间。

市场结果用于判断信息价值，不作为单条事实或分析是否正确的唯一标签。评估错误归类为数据、核验、推理、已定价或时间范围错误。

## 7. 在线观测

统一 OpenTelemetry Trace：

```text
collection_batch
→ document
→ event
→ workflow_run
→ node_attempt
→ agent_run
→ tool_call
→ report_version
→ evaluation_run
```

日志使用 DD-00 的结构化字段；指标采用低基数标签，Event ID 和 Workflow ID 进入 Trace/日志，不作为 Prometheus 标签。

## 8. SLI 与初始告警

| SLI | 初始告警条件 |
| --- | --- |
| 来源采集延迟 | 超过该来源计划间隔 3 倍 |
| 工作流失败率 | 15 分钟窗口超过 5% 且样本 ≥ 20 |
| 引用定位失败率 | 1 小时窗口超过 1% |
| Schema 失败率 | 单模型版本连续 10 次中 ≥ 3 次 |
| 单事件成本 | 超过预算 Profile 硬上限 |
| 审核积压 | 高优先级任务超过约定处理时间 |
| Outbox 积压 | 最老未发布消息超过 5 分钟 |

SLA 在影子运行获得基线后冻结；当前阈值用于发现明显故障，不作为最终承诺。

## 9. 评估运行

EvaluationRun 状态为 `pending | running | succeeded | failed | cancelled`。每次运行保存样本清单、输入快照、配置、逐样本结果和聚合结果。失败样本可单独重试，但聚合结果必须标记不完整。

输出契约见 [evaluation-result.schema.json](./schemas/evaluation-result.schema.json)。

## 10. 仪表盘

- 数据健康：来源延迟、解析失败、隔离队列和重复率。
- 研究运行：节点延迟、模型成本、工具错误和降级率。
- 质量：分类、实体、Claim、引用和人工修改率。
- 审核运营：原因分布、积压、处理时长和退回率。
- 市场验证：按事件类型、来源等级和置信度分桶展示。

仪表盘支持从聚合指标下钻到 Trace 和对象 ID，但遵守内容授权与 RBAC。

## 11. 数据保留与访问

指标聚合长期保留；原始 Trace 按成本和合规策略分层。模型输入输出、授权正文和用户信息不进入普通指标。评估数据集、标签和市场结果仅允许评估角色写入，生产 Agent 只读版本化快照。

## 12. 测试设计

- 时间截面查询拒绝未来文档、行情和修订。
- 非交易日、停牌和事件发生在收盘前后的窗口计算。
- 指标分子分母、空样本、小样本和置信区间。
- 重复 EvaluationRun、部分失败、单样本重试和聚合完整性。
- Trace 上下文跨 HTTP、Worker、Outbox/Inbox 传播。
- 高基数标签检测、日志脱敏和 RBAC 下钻权限。

## 13. 待确认事项

- 行情和行业基准数据源及复权口径。
- 冻结验收集规模和各事件类型样本配额。
- 最终 SLA、Trace 保留周期和成本预算。
- 市场验证是否纳入首期 UI；当前基线为后台任务和内部仪表盘。
